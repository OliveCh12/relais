## Development-machine constraints

- Xcode/CocoaPods were absent initially and are now installed. Expected prebuilt RN/Hermes archives were unavailable. Build the locked sources and disable prebuilt Expo modules that expected React.framework. Launch results are in STATUS.md.
- Android Studio's JBR 25 caused a CMake failure. JDK 17 is installed and pinned through mise. Gradle installed SDK 36, NDK 27.1.12297006 and CMake using existing SDK licenses.
- Expo stable 57 targets RN 0.86. Its supported pair takes priority over the separately published RN 0.87.1. [Expo SDK 57](https://expo.dev/changelog/sdk-57).
- The spike needs two clients and a Mac on the LAN. Standalone two-phone operation is not delivered.
- Signaling HTTP is unencrypted. QR tokens expire; roles, session count and size are bounded. A LAN attacker can observe signaling/tokens; strong transport authentication and SDP pinning remain product work.

## Foundation evidence and primary sources

- Android arm64 compiled and launched on API 36.1; the Kotlin bridge and development WebRTC screen loaded. Xcode builds/launches are tracked separately in STATUS.md. React Native Directory's WebRTC New Architecture warning remains a hardware compatibility concern.
- Kotlin stub methods needed explicit Unit/String returns instead of inferred Nothing before compilation succeeded.
- WebRTC 124.0.8 omits event-target-shim declarations from lib/typescript. A minimal pnpm patch points to shipped src declarations without runtime changes.
- Metro 0.86.3, Worklets 0.10.1 and ESLint 9.39.5 resolve peer conflicts. ESLint 9 remains tooling debt until plugin support for 10. VisionCamera 5.2.3 uses CameraX 1.7.0-alpha03; its major version does not establish OEM stability.
- Actual Android build uses targetSdk/compileSdk 36. No ACCESS_LOCAL_NETWORK request at this target; target 37 work remains open.
- Initial foundation checks covered the HTTP server, development screen and bundles, not a two-phone session. Later iPhone-to-simulator measurements are in [the dated report](../e2e/iphone-webrtc.md).

## O20 — Android post-install incident, September 10

The ARM64 UI build compiled and installed. At 10:54:44, the first Dev Client launch after installation produced a SIGSEGV in `facebook::react::MountingCoordinator::pullTransaction`, on thread `mqt_v_js`. The log is retained locally at `/tmp/relais-ux-android-crash.log`.

Two later cold starts displayed native Home without another crash; Camera → Settings → Framing also passed. The defect is not considered fixed: cause and reproduction remain unknown. Do not attribute it to the camera or development button without evidence. No ABI change or dependency upgrade was used to hide it.
