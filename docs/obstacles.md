## Obstacles de machine et écarts contrôlés

- Xcode absent : pas de SDK iOS/CocoaPods configuré. Prebuild et bundle iOS ne suffisent pas à affirmer « compile iOS ».
- Android Studio possède un JBR ; son adéquation avec le Gradle généré doit être vérifiée. SDK initial partiel : plateforme 37 et build-tools 36 ; NDK/cmdline-tools absents.
- RN 0.87.1 est publié au registre lors de la création, mais Expo stable 57 cible RN 0.86. Le couple supporté Expo/RN prime sur un saut RN isolé non supporté ([Expo SDK 57](https://expo.dev/changelog/sdk-57)).
- Spike = deux téléphones + Mac LAN. La cible produit à deux téléphones sans ordinateur n'est pas livrée par ce spike.
- HTTP de signaling non chiffré : token QR éphémère, rôles distincts, TTL, taille et nombre de sessions bornés. Un attaquant sur le LAN peut observer le signaling et ses tokens ; l'authentification forte/pinning SDP reste à concevoir avant produit.

## Sources primaires consultées le 9 septembre 2026

### Résultats de la fondation

- O20 : APK Android arm64 compilé et démarré sur AVD API 36.1 ; bridge Kotlin et écran WebRTC dev chargés. Xcode/CocoaPods absents : compilation iOS non effectuée. Le marquage WebRTC « Untested on New Architecture » dans React Native Directory reste une réserve ouverte pour les devices et iOS.
- Le JBR 25 d'Android Studio provoquait un échec CMake : JDK 17 installé et verrouillé via mise. SDK 36, NDK 27.1.12297006 et CMake téléchargés par Gradle sur licences SDK déjà présentes.
- Le `Nothing` inféré par les méthodes Kotlin du stub a été remplacé par des retours `Unit`/`String` explicites, puis le module a compilé.
- Le paquet WebRTC 124.0.8 omet le fichier de types de son event-target-shim dans `lib/typescript` : patch pnpm minimal vers les déclarations livrées dans `src`, sans changement runtime.
- Metro 0.86.3, Worklets 0.10.1 et ESLint 9.39.5 verrouillés pour supprimer les conflits de peers. ESLint 9 reste une dette tooling jusqu'au support d'ESLint 10 par les plugins. VisionCamera 5.2.3 dépend de CameraX 1.7.0-alpha03 : validation matérielle requise, aucune stabilité OEM inférée du numéro v5.
- O9 : build effectif `targetSdk 36` / `compileSdk 36`. Pas de demande ACCESS_LOCAL_NETWORK à ce target conformément à la documentation Android ; l'adaptation target 37 reste ouverte.
- O6/O7 : tests du serveur HTTP réussis, écran spike lancé et bundles dev compilés. Aucune session réelle entre deux téléphones, aucune mesure RTT/fps/latence acquise.
