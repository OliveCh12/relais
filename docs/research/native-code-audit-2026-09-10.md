# Native code audit — September 10, 2026

Baseline: `688ad3a` (`feat: add native camera capture and remembered devices`).

Line references describe that baseline. Subsequent implementation and build evidence are tracked in [Project status](../../STATUS.md#native-lifecycle-hardening). This report remains the original audit, including issues outside the first patch.

**Recommendation: harden the existing native recording lifecycle, correct navigation interception and effective settings, then connect the same camera owner to WebRTC. Keep the existing SwiftUI and Compose controls.** A UI rewrite or a combined dependency upgrade would not address the main risks found here.

This is a source review and ordered implementation plan, as requested. No product code was changed. No visual QA, simulator session, installation or native rebuild was performed. The existing architecture boundary check passed during this audit. The 23 passing tests and native build results in STATUS are previous baseline evidence, not tests rerun for this report. Device acceptance steps below are a handoff to the owner, not claims of completion.

## Current truth in 15 lines

1. Local native capture exists; only the historical remote-control contract remains a fixture stub. [STATUS:3](../../STATUS.md#L3), [STATUS:50](../../STATUS.md#L50).

8. Production recording and live preview do not yet run together. [STATUS:3](../../STATUS.md#L3).
9. WebRTC is a separate development flow; release exports were checked for spike/debug exclusion. [STATUS:11](../../STATUS.md#L11).

12. Link bars use measured transport quality, not invented Wi-Fi RSSI. [STATUS:42](../../STATUS.md#L42).
13. A Mac still hosts LAN signaling; standalone two-phone discovery/signaling is absent. [STATUS:42](../../STATUS.md#L42).
14. Native settings, connection and device sheets already exist; the app-owned interface and documentation are English. [STATUS:7](../../STATUS.md#L7), [STATUS:20](../../STATUS.md#L20).

## API corrections before implementation

| Brief assumption                                                         | Verified interpretation and decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The camera owner is still a stub                                         | Contradicted by the current implementation. Keep the real local owners and connect their state to the remote contract later. Do not replace them with another capture session.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Missing explicit Deferred Start flags means missing optimization         | For apps linked on/after iOS 26, supported photo/file outputs enable deferred start by default, and the session automatically runs it by default. Audit readiness and measure startup before changing defaults. The future preview data output needs its own policy. [Apple output behavior](https://developer.apple.com/documentation/avfoundation/avcaptureoutput/isdeferredstartenabled), [session behavior](https://developer.apple.com/documentation/avfoundation/avcapturesession/automaticallyrunsdeferredstart).                                                                                            |
| Responsive Capture makes video recording responsive                      | `isResponsiveCaptureEnabled` belongs to `AVCapturePhotoOutput`. It is not a missing movie-recording switch. Relais has no V1 still-photo capture output. [Apple API](https://developer.apple.com/documentation/avfoundation/avcapturephotooutput/isresponsivecaptureenabled).                                                                                                                                                                                                                                                                                                                                       |
| API 37 dynamically adds any number of camera outputs                     | `CameraCaptureSession.updateOutputConfigurations(List<OutputConfiguration>)` updates existing output configurations, with the same count and matching constraints. It can replace surfaces, including transitions involving deferred surfaces; it cannot arbitrarily append/remove output configurations. CameraX owns the present session, so an interoperable native hook must be demonstrated first. [Android API](<https://developer.android.com/reference/android/hardware/camera2/CameraCaptureSession#updateOutputConfigurations(java.util.List%3Candroid.hardware.camera2.params.OutputConfiguration%3E)>). |
| Every sheet must use Router `formSheet`                                  | Existing SwiftUI `.sheet`/Expo UI `BottomSheet` and Compose `ModalBottomSheet` are actual native presentations. Keep them. Router `formSheet` is relevant if an independent route needs that presentation, not a reason to wrap an existing native sheet in another sheet.                                                                                                                                                                                                                                                                                                                                          |
| Camera Control, volume, Action and AirPods are one unconditional feature | `AVCaptureEventInteraction` is available from iOS 17.2 in the installed AVKit header. Use it, or the SwiftUI capture-event modifier where available, only while capture can handle events. A shutter event is distinct from Camera Control adjustment controls and Lock Screen/Action-button launching. AirPods support also has OS/accessory/region constraints. [Apple interaction](https://developer.apple.com/documentation/avkit/avcaptureeventinteraction), [AirPods availability](https://developer.apple.com/documentation/avkit/avcaptureeventsound).                                                      |
| Direction coordinator is either already usable or merely a rumor         | Apple documents `AVCaptureDeviceDirectionCoordinator` in **AVKit** for iPhone Duo, with the iOS 27.1 SDK. It is absent from this installed SDK. Queue it as a documented, SDK-gated adaptive enhancement; keep `AVCaptureDevice.RotationCoordinator` for current rotation handling. Do not confuse direction with rotation. [Apple camera talk](https://developer.apple.com/la/videos/play/tech-talks/111465/).                                                                                                                                                                                                     |
| New toolbar symbols can simply be pasted into this project               | Apple documents `visibilityPriority`, `toolbarOverflowMenu` and `topBarPinnedTrailing` in its newer SwiftUI material. They are not in the installed SDK. Use currently available native toolbar placements first; adopting newer symbols requires a compiler/SDK availability check, not just a runtime `#available` branch. [Apple SwiftUI updates](https://developer.apple.com/swiftui/whats-new/).                                                                                                                                                                                                               |
| Long foreground streaming requires a foreground service                  | The repository explicitly chooses foreground-only V1. Keep that policy. A background camera service is a separate product/lifecycle decision, not a prerequisite for leaving the camera screen open. [O23](../obstacles.md#L29).                                                                                                                                                                                                                                                                                                                                                                                    |
| Android 17 adaptive behavior is an optional cosmetic choice              | At target 37, orientation/aspect/resizability restrictions cannot opt out on qualifying large screens (`sw ≥ 600dp`). Current target 36 and `orientation: 'default'` must be distinguished from future target-37 validation. [Android behavior changes](https://developer.android.com/about/versions/17/behavior-changes-17).                                                                                                                                                                                                                                                                                       |

### Anti-pattern search results

- No `TouchableOpacity` arrow, second JS navigator or product `getUserMedia` occurrence was found. The boundary check passes.
- `expo-camera` is used by [QrScanner](../../src/components/QrScanner.tsx#L1), as explicitly allowed in AGENTS; it is not the product movie recorder.
- `Pressable` and RN `Modal` exist in generic web/scaffold components: [ui.tsx:95](../../src/components/ui.tsx#L95), [ui.tsx:157](../../src/components/ui.tsx#L157), [ActionButton.tsx](../../src/components/ActionButton.tsx). Mobile resolution selects the SwiftUI/Compose variants for the inspected buttons and sheets. Deleting generic files by keyword would damage the web presentation.
- iOS Rec/Stop is a SwiftUI `Button` containing native shapes; Android uses a Compose `IconButton`. These are not JS-painted controls. See [iOS:201](../../modules/relais-camera-engine/ios/AppleCameraView.swift#L201), [Android:17](../../src/components/CameraIconButton.android.tsx#L17). Native SDKs do not provide an embeddable copy of every Camera.app/Pixel Camera control.
- Manual camera top-bar layout and explicit close actions do exist. Their navigation placement should improve, but a native viewfinder overlay is not itself a second JS navigation stack.
- The SwiftUI `NavigationStack` inside the settings sheet supplies that sheet's native title/Done toolbar. It is not a second React Navigation container.

## Ordered implementation plan — 11 items

Each item is a separate reviewable slice; do not combine dependency upgrades. Device checks are short functional acceptance steps except the existing sustained-capture gate, which is deferred until the native tee exists.

1. **P1 — Harden native owner and recording truth.** Address G01/G02/G04–G07 with small patches; include G08 when changing recovery. Model visible/foreground/configuring/finalizing independently from gallery import. Keep truthful stub flags and OS-confirmed gallery success. **Done:** on an available iPhone/Android, start a take, press Stop and leave/lock during finalization; no owner restarts after exit, the file either imports once or remains recoverable, and settings describe what the native output actually applies. Regression checks cover stale callbacks and failed reconfiguration without an elaborate UI test suite.
2. **P1 — Restore native navigation ownership and finish chrome placement.** Address G03; use native-stack for idle back navigation and a focus-scoped native confirmation for an active take. Preserve existing native settings/device/QR sheets. Move navigation and overflow actions into supported SwiftUI toolbar/Compose app-bar slots where they fit the capture screen; retain one root route tree and the native shutter. **Done:** Android Back while idle returns normally; Back with a take opens one native confirmation; cancel keeps recording; confirm finalizes before leaving. iOS idle swipe can return, while leaving during a take follows the same save policy. Sheet dismissal does not stop preview. Gesture animation inspection is left to the owner.
3. **P1 — Close the local-recording hardware gate before more features.** Use the existing short protocol, update its evidence and investigate O20 if it reproduces. **Done:** iPhone 17 Pro records and plays a short portrait and landscape 4K30 take with audio; a supported Cinematic take is correctly identified; one available physical Android does the same at its supported profile. Denied gallery access retains a recoverable file. Record actual codec, resolution, duration, rotation and import outcome. Missing Android hardware stays explicitly blocked; 4K120 remains unvalidated until separately measured. No broad screenshot pass.
4. **P1 — Add native frame injection from the same session.** Add an AVFoundation video-data sink alongside the movie output; on Android prove a native CameraX analysis/output hook under VisionCamera's existing owner. Feed WebRTC's native source with bounded buffers and preserved timestamps/rotation. Start with the established reduced preview profile; validate every additional output combination. **Done:** two physical phones show the preview while the Camera writes a playable local file; cutting Wi-Fi for five seconds leaves recording intact. Then run the already specified 20 start/stop cycles and 20-minute ownership/buffer check. If Cinematic/HDR cannot coexist with the extra sink on a device, expose the actual combination limitation; do not silently lower the master profile.
5. **P1 — Add supported iOS hardware Rec/Stop.** Connect AVKit capture events to the same guarded commands as the shutter. Keep hardware settings adjustment and Lock Screen launch as separate scope. **Done:** one supported hardware press starts one take, the next stops it; an event during saving or after leaving cannot start a recording. The saved file confirms the commands, not a UI echo.
6. **P2 — Evaluate Android dynamic sessions and logical metadata.** Only after item 4, check whether the pinned owner can update an eligible preconfigured sink safely. Make API-37 compilation/target changes a separate compatibility slice with current-device fallback; assess local-network permission changes at the same target gate. **Done:** an eligible physical Android can attach/detach the preview sink without invalidating the local file or opening another camera. Unsupported devices retain the already validated fixed-output path. A documented infeasibility result is acceptable; a second camera owner is not.
7. **P1 — Promote a real Monitor route and remote commands.** Implement transport behind the product boundary, exchange Camera capabilities and acknowledge native command outcomes. Reuse the existing native sheets and receiver surface; retire the release demo path only when this works. **Done:** Monitor starts/stops a take on the Camera, sees actual state/quality, and cannot report a successful recording before the Camera writer confirms it. The file is saved on Camera, not Monitor. Both iOS-to-Android directions must pass.
8. **P1 — Make two-phone pairing work without the Mac.** Add a foreground-only phone rendezvous/discovery strategy compatible with both OSes, including an authenticated binding for pairing/signaling. Preserve QR/paste fallback and the existing secure identity model. **Done:** with Mac disconnected and internet off, scan once and establish the same peer-to-peer preview; expired or unauthorized descriptors fail clearly. Backgrounding the Camera withdraws availability. No cloud or vendor-only transport.
9. **P1 — Bring remembered devices into that product flow.** Reuse registry, handshake, private presence, native rename and forget sheets. **Done:** after restarting both apps, re-share on Camera and tap its saved name on Monitor; reconnect without another QR, while a forgotten pairing requires a new scan. Renaming must not alter identity or trust.
10. **P1 — Wire sustained-capture diagnostics and preview degradation.** Connect existing native event contracts, measure sparse telemetry and implement the documented pressure policy. **Done:** an optimized physical-device run records actual temperatures/thermal states, battery and output counters; lowering preview load leaves a playable master file. UI refresh, video fps and transport latency remain separate measurements. No guarantee of maximum refresh or zero thermal interruption.
11. **P2 — Add adaptive session panes and newer native chrome.** Use window/size-class state within the existing route, with the preview and controls arranged for available space. Decide tablet enablement explicitly. Adopt documented newer toolbar/direction APIs only with a compatible SDK and device gate. **Done:** the owner's tablet/fold/small-window check can reach shutter, close and settings without clipping; resizing or changing display does not open a second owner or falsely change the recording format. Keep Store publication, cloud, Handoff and new camera modes out of this slice.

## First three P0/P1 work items: concrete patch boundaries

O20 is an existing P0 investigation, not a patch with an established target. Do not fabricate a source fix or change packages to conceal it. The following are the first three actionable P1 plan items; item 3 includes O20 evidence if encountered.

### 1. Native lifecycle, applied settings and file recovery

**Files:** `modules/relais-camera-engine/ios/AppleCameraModel.swift`, `AppleCameraPreview.swift`, `AppleCameraView.swift` only for effective-state display, `AppleCaptureSettings.swift` if sharing zoom conversion; Android `src/LocalCamera.tsx`, `src/RecordingController.ts` inside the module; platform `RecordingLibrary` files only for recovery receipts. Extend existing recording/profile tests for actual state-ordering regressions. Keep each fix independently reviewable.

**Exact APIs:** `AVCaptureSession.beginConfiguration()/commitConfiguration()`, `canAddInput`, `canAddOutput`, `startRunning()/stopRunning()` on the existing queue; `AVCaptureFileOutputRecordingDelegate.fileOutput(_:didFinishRecordingTo:from:error:)`; `AVCaptureConnection.isVideoStabilizationSupported`, `activeVideoStabilizationMode`; `AVCaptureDevice.videoZoomFactor` and gated `displayVideoZoomFactorMultiplier`; `AVCaptureDevice.RotationCoordinator` on iOS 17+, guarded `AVCaptureConnection.videoOrientation` below it. Preserve `PHPhotoLibrary.performChanges` confirmation. Android retains the pinned VisionCamera recorder callback over CameraX `VideoRecordEvent.Finalize`, then MediaStore insertion with `IS_PENDING` and a confirmed publication update. Gallery-copy completion must not be the camera deactivation signal.

**Not touched:** dependency versions, public fixture success flags, transport, rendering engine, CameraX owner replacement, generated CNG directories, ProRes/Log/RAW. A new permission prompt or a deployment-target increase is not a substitute for a compatibility fix.

### 2. Native navigation and busy-state confirmation

**Files:** `src/screens/Camera.native.tsx`, `src/screens/Camera.ios.tsx`, the native camera view/module only to expose the minimal busy/close outcome needed by the route. `app/_layout.tsx` only if a concrete route presentation changes; platform camera chrome components only for supported native placement.

**Exact APIs:** existing Expo Router native `Stack`, focus-scoped lifecycle via `useFocusEffect`, existing RN `Alert.alert` and SwiftUI `confirmationDialog`; native SwiftUI `ToolbarItem` with currently supported placements and Compose Material `TopAppBar` where needed. Let the stack/library own default Android back dispatch. Android's `OnBackPressedCallback`/Compose `PredictiveBackHandler` are platform mechanisms, not a reason to register a second competing handler. The pinned navigation library must be checked before choosing a busy-removal guard; an unconditional `beforeRemove.preventDefault()` is not the proposed solution. [Android back guidance](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture), [RN BackHandler semantics](https://reactnative.dev/docs/0.82/backhandler).

**Not touched:** a second navigation tree, native settings/device sheets, system theme, the recording owner, custom gesture-progress animations, blanket conversion of all sheets to Router `formSheet`. Canceling navigation must not stop the take.

### 3. Complete recording evidence

**Files:** `e2e/local-recording.md`, `docs/capability-matrix.md`, `STATUS.md`; `docs/obstacles.md` only when evidence changes an obstacle. Existing development-only native diagnostics can be extended narrowly if the requested file facts cannot otherwise be observed.

**Exact APIs / observations:** `AVURLAsset.load(.duration)` and `loadTracks(withMediaType:)`, video track transform/format descriptions; PhotoKit's successful change completion and subsequent Photos playback. Android `MediaMetadataRetriever`/`MediaExtractor` for actual encoded metadata, plus the published MediaStore URI and gallery playback. Native diagnostics complement rather than replace owner playback. Observe `AVCaptureSession.runtimeErrorNotification` and native crash logs when interruptions occur.

**Not touched:** production UI redesign, screenshot automation, repeated builds without a native change, performance certification from Metro, invented Pixel evidence or a claim that a single successful start proves 4K120 recording. Run `pnpm check` once for the relevant subsequent code patch; rebuild only the affected native target. Current audit changed documentation only.

## Read in the repository — preserve these decisions

- **Native stack and ownership:** [AGENTS](../../AGENTS.md), [architecture](../architecture.md). One app, two roles, one native camera owner. SwiftUI on iOS, CameraX/Compose on Android, shared JS domain; frame buffers remain native.
- **Locked stack and durable native changes:** [package.json](../../package.json), [STATUS tooling](../../STATUS.md#L86). Expo 57.0.21, RN 0.86.3, React 19.2.3, Router 57.0.20, VisionCamera 5.2.3, WebRTC 124.0.8 and Nitro 0.37.1; CNG outputs are disposable. No grouped upgrades or cosmetic refactoring.
- **Truthful status:** [STATUS](../../STATUS.md), [fixture](../../modules/relais-camera-engine/fixtures/capabilities.json). Keep `source: stub`, `canRecord: false`, `canPreview: false` for the unconnected remote contract. Local real capture is documented separately.
- **Master file and independent transport:** [capture research](capture-ui-and-recording.md), [obstacles](../obstacles.md). Camera records locally; only confirmed PhotoKit/MediaStore imports become gallery success. Network loss must not stop recording.
- **Native presentation:** [native UI decisions](../native-ui-ux.md). Keep real platform controls, SF Symbols/Material Symbols, accessible labels, system theme outside capture, native sheets and a fixed viewfinder. No tabs merely for appearance and no full Camera.app clone.
- **Hardware-derived combinations:** [capability matrix](../capability-matrix.md), [native camera research](native-camera-capabilities.md). Preserve native formats, compatible resolution/fps/HDR combinations, Cinematic depth checks and honest limitations. Do not equate stabilization with Cinematic capture or hardware enumeration with a certified file.
- **Development-only spike:** [spike README](../../src/spikes/webrtc-preview/README.md), [boundary check](../../scripts/check-boundaries.mjs), [dev route](../../app/dev/webrtc.tsx). Keep isolated `getUserMedia`, audio off and measured preview parameters until the native product transport exists.
- **Remembered-device trust:** [device research](remembered-devices.md). Preserve random identifiers/secrets, SecureStore, mutual pairing acknowledgments, ephemeral availability, rename/forget and revalidation before reconnect. Saved does not mean nearby or connected.
- **Foreground and performance policy:** [energy/performance](../energy-and-perf.md), [O23](../obstacles.md#L29). Keep foreground-only V1, native keep-awake and preview-first degradation. Avoid per-frame JS and distinguish UI refresh from capture fps.
- **Evidence boundaries and scope:** [e2e protocols](../../e2e/README.md), [STATUS](../../STATUS.md). Keep simulation, compilation, physical operation and sustained performance separate. The owner performs visual QA. No accounts, cloud media, SFU, vendor-specific cross-OS transport, product multicam or Store publication.
