# Relay gesture root and device settings — September 11, 2026

The root layout now wraps the entire Expo Router navigator in GestureHandlerRootView with flex: 1. Both local and remote React Native gesture surfaces inherit that root. RTCView stays inside a sized, non-collapsible native container, with Android zOrder 0 and touches handled above the video surface. The renderer reports its actual video dimensions; contain/cover mapping excludes letterboxes and accounts for cropping. This addresses the reported gesture-root exception without changing the video encoder or capture ownership. [Gesture Handler 2 installation](https://docs.swmansion.com/react-native-gesture-handler/docs/2.x/fundamentals/installation/).

Local iOS gestures use UIKit recognizers on AVCaptureVideoPreviewLayer. Layer coordinates are converted through Apple's preview-layer API; native shape layers draw the focus square and exposure rail. Android uses VisionCamera's native CameraX metering/exposure controls. Monitor metering sends bounded normalized image coordinates through the paired command channel; the capture owner removes the outgoing frame rotation before native metering. The outgoing stream is unmirrored on both platforms. Exposure remains EV-based, including Android's native compensation step. [Apple coordinate conversion](<https://developer.apple.com/documentation/avfoundation/avcapturevideopreviewlayer/capturedevicepointconverted(fromlayerpoint:)>), [CameraX surface metering](https://developer.android.com/reference/androidx/camera/core/SurfaceOrientedMeteringPointFactory).

Hold and drag feedback runs on the UI thread. The JavaScript/native control boundary carries control values only, with one operation in flight and a single latest pending exposure value. No video frame crosses JavaScript. The existing native exposure slider remains available in settings as an accessible alternative. Plain SF Symbol buttons and Material IconButtons provide comfortable 48-point/dp targets; camera controls do not use Glass styling.

Device information and remote camera settings share one stack page. SwiftUI Form/DisclosureGroup and Material Card/ListItem groups provide the platform presentation. Connect/Live is in the native app bar. Connection measurements are collected only while the connected device page is focused; the camera's connection page can also inspect its link. My cameras remains a presence list.

Offline preferences persist separately from live camera state. The last reported capability snapshot is cached with the saved device; format IDs are split into bounded SecureStore entries so a large catalog does not require one oversized secret-storage value. Invalid cache data never deletes pairing credentials. Preferences are applied only after an explicit connection, with fresh native acknowledgements and capability checks after each mode/lens/format change. The Android owner returns its committed capture state in settings acknowledgements. A disconnect invalidates the pending application by session generation. A failed preset remains available for review or discard.

See [bidirectional acceptance steps](../relay-testing.md). Dependency versions, native camera ownership, original-file recording and gallery finalization are unchanged by this pass.
